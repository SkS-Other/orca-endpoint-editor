# AGENTS.md

Правила для агента, который правит этот репозиторий. Репозиторий локальный: remote нет и не
заводится, никуда не публикуется.

## Что это

Плагин Orca `local.endpoint-editor` — панель «Адреса серверов» в правом сайдбаре. Она меняет
host/port/схему сохранённых удалённых окружений Orca и умеет проверять адреса на доступность.

```
orca-plugin.json     манифест: id, capabilities, панель endpoints
src/worker.ts        вся логика: канал через терминал, правка файла, probe, test
src/panel.tsx        UI: вкладки окружений, поля, пресеты, проверки
src/protocol.ts      контракт панель ↔ worker (типы запросов и ответов)
src/panel.check.ts   сценарии для `orca plugin check`
src/*.test.ts(x)     тесты на `orca/testing` (node:test)
tsconfig.json        типы только для рантайм-кода, тесты исключены
```

Сборки нет: Orca сама транспилирует `.ts`/`.tsx` при загрузке. `package.json`, бандлера и
lock-файлов в проекте нет намеренно.

## Как это работает и почему именно так

В плагинном API Orca нет ни файловых методов, ни методов для окружений, ни вкладки в Настройках.
Единственный путь к `~/Library/Application Support/orca/orca-environments.json` — реальный шелл:

1. worker создаёт терминал `server-endpoints` в активном worktree;
2. печатает в него короткую команду через `terminal.sendText`;
3. читает вывод через `terminal.read`;
4. скрипт на python3 правит JSON, держит бэкапы и проверяет порт.

Терминал — плохой канал, и ниже четыре правила, которые держат его в узде. Все они сторожатся
тестами; ломать их нельзя.

### 1. Одна команда за раз

`run()` завёрнут в очередь (`queue`). Две параллельные `sendText` склеиваются в одну строку,
оставляют шелл в незакрытой кавычке (`dquote>`) и он молча висит — при живом `terminal.read`.

### 2. Короткие строки

Строка длиннее ~180 символов может быть обрезана PTY, и кавычки снова разъезжаются. Скрипт едет
base64-чанками по 120 символов в `/tmp/orca-endpoint-editor*`, декодируется и запускается отдельной
короткой командой.

### 3. Маркеры печатаются двумя литералами

`printf '%s%s' 'A' 'B'`, а не `echo 'AB'`: иначе маркер есть в эхе самой команды и сходит за её
вывод. Плюс эхо последней строки склеивается с первым выводом программы, поэтому длина ищется
регуляркой, а чанки — только строки чистой base64 длиной ≥ 32.

### 4. Служебный шелл — только в активном worktree

`terminal.sendText` отказывает любому терминалу вне активного worktree (`terminal is outside the
active worktree`, `no active worktree is available for terminal input`), а `terminal.create`
принимает любой workspace. Поэтому:

- терминал создаётся в активном локальном workspace, а не в «первом локальном»;
- сохранённый `terminalId` сверяется с `workspace.readContext.terminals` до первого ввода: id из
  другого worktree — это не мёртвый шелл, а чужой терминал;
- если активен workspace на удалённом сервере (или активного нет), worker сам зовёт
  `workspace.open` для локального: последний использованный → папка → первый локальный.

Шелл обязан быть на этой машине, потому что файл окружений — её собственный. На удалённом хосте
тот же путь указывает на его стор, и «успешная» правка испортила бы чужой конфиг.

Вернуть прежний удалённый workspace плагин не может: в этом состоянии `workspace.readContext`
возвращает `null`, и id удалённого worktree недоступен.

## Схема — часть адреса, а не окружения

`wss://` годится только там, где на порту действительно TLS. Пресет хранит схему вместе с
host/port, панель передаёт её в `endpoints.set`, worker пишет `<схема>://host:port` как есть и не
наследует сохранённую. Иначе переключение с `wss://домен:443` на оверлей даёт
`wss://10.x:40455` и не работает.

Пресеты без схемы (сохранённые до её появления) получают её при загрузке: 443/8443 → `wss`,
приватные и оверлейные адреса → `ws`, остальное → `wss`.

## Capabilities и подтверждение

`orca-plugin.json` объявляет ровно то, что нужно: `workspace:read`, `workspace:write` (нужна для
`workspace.open`), `terminal:send`, `terminal:read`, `storage:own`.

- Правка кода в dev-папке подтверждения не требует: `orca plugin dev load .` обновляет отпечаток.
- Новое расширение прав, смена уровня исполнения или `commands`/шорткатов — новый отпечаток,
  `orca plugin dev load .` его напечатает, ставится `--approve <fingerprint>`.
- Убирать capability из манифеста, если она больше не используется, и не добавлять «на всякий
  случай»: каждая строка — это новый отпечаток и вопрос пользователю.

## Проверка перед коммитом

```sh
orca plugin validate .    # манифест и типы запросов
orca plugin test .        # 28 тестов: панель + worker
orca plugin check .       # 4 сценария панели: empty, unreachable, presets, managed
npx tsc -p .              # типы рантайм-кода (нужны .orca/types, их создаёт dev load)
```

Живая проверка (нужен локальный workspace и подтверждённый плагин):

```sh
orca plugin dev load .            # печатает отпечаток, если нужно подтверждение
orca plugin dev reload            # после правок
orca plugin dev request . endpoints.list --data '{}' --json
orca plugin dev request . endpoints.probe --data '{"targets":[{"host":"127.0.0.1","port":5433}]}' --json
orca plugin logs local.endpoint-editor
```

Один проход через шелл ≈ 8 с (`endpoints.list`), неудачная TLS-проверка ≈ 18 с. Это свойство
канала, а не регресс: не «оптимизировать» таймауты, не разбивать проход на несколько `sendText`.

## Где лежат данные

| Путь | Что там |
|---|---|
| `~/Library/Application Support/orca/orca-environments.json` | окружения и их эндпоинты; режим 600, правит только шелл |
| `…/orca-environments.json.bak.<epoch>` | бэкапы рядом с файлом, хранятся последние 10 |
| `~/Library/Application Support/orca/plugins-data/local.endpoint-editor/storage.json` | пресеты, `terminalId`, `workspaceId` |
| `/tmp/orca-endpoint-editor*` | временные скрипты и чанки, удаляются после запуска |

Живые эндпоинты и пресеты — разные вещи: пресет это заготовка адреса, применение переписывает
эндпоинт в `orca-environments.json`. Failover в Orca нет: у окружения один эндпоинт
(`ws-<envId>`), повторный пейринг его перезаписывает, поэтому «домен и оверлей одновременно»
невозможно — только переключение.

## Стиль правок

- Минимальные изменения по месту. Не рефакторить соседний код, не «улучшать» форматирование.
- Комментарии в коде — по-английски и только про «почему», пользовательские строки — по-русски.
- Правки UI сопровождать сценарием в `src/panel.check.ts`, правки worker'а — тестом в
  `src/worker.test.ts`. Тест должен падать без правки.
- Тесты не типизируются корневым `tsconfig.json` (`find()` возвращает `TestElement | null`);
  они проверяются запуском, а не `tsc`.
- `version` в `orca-plugin.json` поднимается при выпуске, не на каждой правке.
- Новые зависимости не добавлять: плагин живёт на встроенных модулях Node и `python3` из PATH.
